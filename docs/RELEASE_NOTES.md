# Career Assistant v0.1.13 — Compatible browsers and durable setup choices

Browser preparation requires Node 20+, working paired npm, the tested
@playwright/mcp@0.0.83 CLI and an actual Chromium launch. Incompatible Node 18 is
preserved while a private LTS is prepared when allowed. Component deferrals are
saved independently from capability inspection, with explicit browser/search
resume options and compatible handling of older deferred steps.

Dependency installations validate writable directories, nested links, actual venv
prefix/package destinations and caches. External complete runtimes remain usable
without changes; incomplete linked environments use a local fallback. A linked
runtime already in use is recognized by its resolved prefix rather than spawning
itself again. Existing private TeX resources are rediscovered after metadata
recovery and verified offline before downloading.

Only standard reusable software and fictional tests ship. Account/model/site
acceptance remains scoped in docs/VALIDATION.md; this is a development preview.

# Career Assistant v0.1.12 — Reliable native setup and accurate dependency checks

Windows interpreter probes exchange ASCII JSON and verify the final executable,
preserving Chinese paths even with GBK output. Native uv verification uses .NET
SHA-256 directly and does not depend on shell module discovery.

Setup rejects duplicate JSON keys, non-integer versions and incomplete/unknown
steps before installation or replacement. It validates every existing directory
component before creating state, locks or recovery backups, including when the
final file does not exist. Explicit recovery still preserves exact original bytes.

Doctor probes the saved local runtime instead of borrowing the parent Python's
package readiness. A missing/broken runtime leaves PDF import/render pending with
an actionable setup recovery message; text/profile/source-only work can continue.

Regression coverage includes actual Windows shells with GBK and Chinese paths,
linked directory preservation, ambiguous consent and broken selected runtimes.
This remains a development preview; current evidence and platform/site limits are
recorded in docs/VALIDATION.md. No user data, credentials or runtime state ships.

# Career Assistant v0.1.11 — Saved consent and MCP configuration repairs

Damaged or unreadable installer state no longer becomes a fresh automatic install.
Setup preserves the original and requests a reviewed recovery choice. The new
recover-setup helper verifies a raw-byte backup before saving defer/resume and
installs nothing. Text/profile/source-only work can continue independently.

Browser registration parses TOML and recognizes equivalent quoted, dotted and
inline server definitions. It validates candidate config and all requested hosts
before writing, preserves conflicts, and rejects linked paths outside the project.
Python 3.10 receives the conditional tomli parser. Windows PowerShell 5 runtime
installation now handles successful native stderr progress correctly.

This development preview includes automatic private dependency setup, immutable
per-application resume artifacts and the earlier duplicate/preference repairs.
CI and release workflows validate only reusable public source and fictional tests;
no profile, credentials, private runtime or generated personal skill is published.
Actual platform/model/site acceptance remains scoped in docs/VALIDATION.md.

# Career Assistant v0.1.10 — Automatic first-use environment setup

Initialization now checks and reuses existing runtime/PDF/browser capabilities,
automatically installs missing local dependencies when permitted, verifies them,
and resumes saved onboarding. Native Windows/POSIX bootstraps cover a missing
Python runtime. Official PyPI wheels, checksum-verified Tectonic/Node assets,
canonical-template resource warming and a private Playwright MCP fallback are
supported. No global PATH, registry, model or approval policy is changed.

Denied installation steps require the specific user permission; successful steps
are retained. New browser configuration remains pending host reload/trust until
the live API is available. Account login, CAPTCHA/2FA and real-site acceptance
remain separate. See docs/VALIDATION.md for actual evidence and platform scope.

# Career Assistant v0.1.9 — Download audit fixes

Applications keep an immutable hashed package for each attempt, so editing a later
draft preserves the original submitted/uncertain PDF and supporting evidence.
Legacy live-path records are protected before rerender; missing originals require
recovery from a verified local backup rather than a replacement attachment.

Distinct requisitions with identical employer/title can be tracked separately.
Title-only matches have an explicit scoped user-review path, while true duplicates
and uncertain previous submissions retain their guards. Restore uses the same
identity rules and preserves historical snapshots without schema rewriting.

Preference shapes are validated before saving and malformed older fields can be
repaired through the helper. Windows atomic replacement tolerates short sharing
conflicts with bounded retries; persistent denials preserve existing data.

The native-host runner now starts from an uninstalled public download outside the
source repo. See docs/VALIDATION.md for actual verification and environment limits.
This remains a development preview; no hosted service or real application is added.

# Career Assistant v0.1.8 — Development preview

Users can ask the assistant to back up, restore and inspect changes to their local
career knowledge. Private backups include sources, facts, preferences, private
routes, resume packages and application evidence; credentials, browser sessions,
submission grants and installed host skills are excluded. Restores verify a plan,
save a prechange backup, preserve newer Submitted/uncertain attempts and support
rollback after interruption. Schema 1-to-2 migration preserves facts and source
references while adding workspace identity and preference revision metadata.

GitHub CI now tests the standard software across Windows, Linux and macOS, runs
fictional browser scenarios and verifies public bundle contents. Version tags run
the same checks before publishing the ZIP, startup guide and SHA-256 files.
Current and historical acceptance records are separated for easier review.

Validation: 95 Python tests passed in each of five hosted OS/Python combinations,
21 fictional browser scenarios passed, clean extraction and both generic skill
installations passed, and two real one-page PDFs were visually checked. The first
CI's four distribution files matched the corresponding local build byte for byte;
the tag workflow repeats checks before publishing this version.

This remains a development preview. Previous Codex conversation and supervised
local browser evidence is retained; this release's maintenance checks are helper
tests. Claude Code conversations remain deferred, macOS desktop conversations
and real Workday/employer submission behavior remain unverified. See
docs/VALIDATION.md for actual scope and evidence.

The public package contains reusable software, workflows, schemas, the unchanged
one-page template and clearly fictional test fixtures. Users provide their own
knowledge locally after download. Projects remain off by default and, when
requested with evidence, appear after Work Experience and before Education.
